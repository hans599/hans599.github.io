# SFT

监督微调（Supervised Fine-Tuning, SFT） 的核心，就是使用预先验证过的、带标签的数据，来让一个已经预训练好的大语言模型（LLM）适应特定的下游任务。

简单来说，SFT就是在预训练模型的基础上，用标注好的“问题-答案”数据，进行一次有监督的训练。

<!-- more --> 


SFT的核心目标是让模型掌握指令遵循能力——用户问什么，它就回答什么，而不是天马行空地自由发挥。



## 与预训练有什么区别？

| 对比维度 | 预训练 (Pre-training) | 监督微调 (SFT)                      |
| :------- | :-------------------- | :---------------------------------- |
| 训练数据 | 海量无标注文本         | 少量高质量标注数据                   |
| 数据特点 | 每条数据长度尽量填满   | 数据保持原始长度                     |
| 学习目标 | 学习语言通用知识       | 学习特定任务和对话格式               |
| 角色区分 | 没有角色概念           | 引入 system、user、assistant 等角色 |
| 输出控制 | 不会停止生成           | 学习用 eos_token 结束回答           |


## 与CV领域微调的差异

SFT跟以往计算机视觉中的微调并无本质区别，都是将一个与训练好的模型，用特定的数据集再进行训练。


- 在 CV 中：我们在 ImageNet 上预训练 ResNet，然后用猫狗数据集微调最后几层，让它学会区分猫和狗。

- 在 NLP (SFT) 中：我们在海量文本上预训练 GPT，然后用客服对话数据集微调整个模型，让它学会用客服的语气回答问题。

它们的数学原理和训练流程完全一致：加载预训练权重 → 定义损失函数 → 在新数据上反向传播 → 更新参数。所以，从技术实现上看，它们没有本质区别。

| 维度     | CV 微调（传统）                       | NLP SFT（大语言模型）                                      |
| :------- | :------------------------------------ | :--------------------------------------------------------- |
| 模型规模 | 通常较小（百万至亿级参数）             | 规模巨大（数十亿至万亿级参数）                              |
| 数据形式 | 图像分类、目标检测的标注图片           | 对话、指令的问题-答案对                                     |
| 训练方式 | 常冻结主干网络，只微调最后几层或分类头 | 全量微调所有层，或使用 LoRA 等参数高效微调                  |
| 核心目的 | 特征迁移：学习特定领域的视觉特征       | 行为对齐：学习“遵循指令”的交互方式，让模型输出更符合人类偏好 |
| 数据规模 | 数千到数十万张图片                    | 通常需要数千到数十万条高质量指令数据                        |


两者的边界正在模糊。在视觉-语言大模型（如 LLaVA）中，SFT 已经被用于微调多模态模型以遵循指令，这使得 SFT 的定义从“纯语言”扩展到了“多模态”。


## 全量微调（FFT）与参数高效微调（PEFT）


全量微调： Full Fine-Tuning
参数高效微调：Parameter-Efficient Fine-Tuning


| 方式     | 更新参数   | 资源需求 | 适用场景               |
| :------- | :--------- | :------- | :-------------------- |
| 全量微调 | 所有参数   | 高       | 数据充足、追求最优效果 |
| LoRA     | 仅低秩矩阵 | 低       | 资源受限、快速适配     |
| QLoRA    | 量化+LoRA  | 极低     | GPU 显存极其有限       |


SFT, FFT, PEFT的关系
```text
监督微调 (SFT) —— 核心理念：用标注数据让模型学任务
            │
            ├── 全量微调 (FFT) —— 方法：更新所有参数
            │
            └── 参数高效微调 (PEFT) —— 方法：只更新部分参数
                          │
                          ├── LoRA
                          ├── QLoRA
                          └── Adapter, Prefix-Tuning...
                          
```


# SFT的关键环节


数据质量直接决定微调效果，需要从以下几个维度精心设计


| 维度         | 说明                                    |
| :----------- | :------------------------------------- |
| 多样性       | 覆盖翻译、问答、写作、推理等多种任务类型 |
| Prompt多样性 | 同一意图用不同方式表达，避免过拟合关键词 |
| 长度均衡      | 短数据与长数据搭配，防止注意力退化       |
| Answer多样性 | 避免大量数据输出同一句话，防止模型学偏   |
| 多轮对话能力 | 学会判断新问题是否与历史对话相关         |



高质量数据从哪来？

- 顶级模型生成：GPT-4、Claude 3 等，质量有保障

- 开源模型生成：Qwen-72B、DeepSeek-MoE 等，可本地部署

- 业务定制数据：针对特定场景（如对联、猜灯谜）专门构造

一些推荐的高质量数据集：

| 数据集名称            | 特点与规模                                                    | 适用场景             |
| :------------------- | :------------------------------------------------------------ | :------------------ |
| GPT-4all             | 约 40 万条英文配对数据，结合了 OIG、P3 和 Stackoverflow 的子集 | 通用问答、创意问答   |
| RedPajama-Data-1T    | 约 1.2 万亿 Token，完全开源，遵循 LLaMA 方法                   | 预训练（非微调）     |
| OASST1               | 高质量、人工编写和标注的多语言对话树（约 6.6 万棵）             | 改进对话和回复质量   |
| databricks-dolly-15k | 约 1.5 万条人工编写的提示-回复对                               | 问答、文本总结等任务 |
| AlpacaDataCleaned    | 清理后的 Alpaca、GPT_LLM 和 GPTeacher 数据                    | 指令遵循             |
| GPT-4-LLM            | GPT-4 生成，含英文/中文指令数据（共约 6.1 万条）               | 指令微调、RLHF       |
| GPTeacher            | GPT-4 生成，约 2 万条，含角色扮演等新任务                      | 多样化指令微调       |
| Alpaca               | text-davinci-003 生成，约 5.2 万条英文指令数据                 | 增强模型指令跟随能力 |


训练配置
关键超参数包括：
- 学习率（Learning Rate）：SFT 的学习率通常远低于预训练阶段
- Epoch 数量：通常 1-3 轮即可，过多容易过拟合
- Global Batch Size：影响训练稳定性和收敛速度



# 常见挑战与应对

## 幻觉问题

表现：模型编造事实。

应对：
- 狭义幻觉（事实性错误）：通过调参和数据清洗缓解
- 广义幻觉（事实与编造混合）：更依赖 RAG、工具调用等外部知识注入



## 过拟合

表现：模型只认识训练数据中的特定表述，泛化能力差。

应对：
- 保证数据多样性
- 控制训练轮数
- 用验证集监控训练状态



# 总结 

SFT的核心价值在于，它以极低的成本将预训练模型的通用语言能力，引导到特定的任务场景。

预训练给了模型“语文能力”，SFT则教会它“如何回答问题”。没有SFT，大模型再庞大也只是个高成本的胡言乱语机器；有了SFT，它才能真正服务于我们的需求。
