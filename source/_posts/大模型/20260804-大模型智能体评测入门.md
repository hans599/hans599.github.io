当前，大模型早已不是仅供闲聊的“花瓶”。从自动写代码到操控智能体（Agent）自主完成订票、数据分析甚至科研实验，大模型正在从“对话工具”进化为“数字员工”。

但随之而来一个关键问题：如何科学地评价一个模型“干得好不好”？

写诗可以凭审美，但让AI操作浏览器订机票、调用工具写报告，这些任务需要一整套严谨的评测体系。评测看似是个“技术活”，本质上是个认知活——得先想清楚“好”的标准是什么。

# 为什么要评测——信任的前提


评测的本质不是“出题考AI”，而是建立信任的桥梁。在把任务交给AI之前，需要知道它的能力边界在哪里。

**评测回答三个核心问题**
- 能做什么？ —— 模型擅长什么类型任务（数学推理？代码生成？多轮对话？）

- 不能做什么？ —— 在哪些场景下会翻车（长上下文丢失？工具调用失败？）

- 差距有多大？ —— 相比上一代或竞品，进步/退步在哪儿？

**评测的三个现实意义**
- 选型依据：企业要在众多模型中选一个接入业务，得有数据支撑，不能靠“感觉”。

- 迭代方向：研发团队需要知道弱点在哪，才能针对性优化。

- 风险控制：在医疗、金融等高风险领域，误判的代价极高，评测是安全底线。

# 评测流程与指标体系——搭建完整框架

一套完整的评测方案，需要从“感性”走向“理性”。

```
定义评测目标 → 选择数据集 → 设计评测指标 → 执行评测 → 结果分析与迭代
```

**核心评测指标**
常用指标可以分为三类：

① 基础能力指标（客观题）

- 准确率（Accuracy） ：答对的题数占比，最直观

- F1-Score：平衡精确率和召回率，适合不平衡数据集

② 生成质量指标（主观题）

- BLEU / ROUGE：衡量生成文本与参考答案的n-gram重叠度，常用于翻译、摘要

- BERTScore：利用BERT语义向量计算相似度，比BLEU更接近人类判断

③ 智能体专项指标（Agent特有）

- 任务完成率（Task Success Rate） ：最终目标是否达成

- 步骤效率（Step Efficiency） ：完成任务用了多少步，步数少意味着策略优

- 工具调用准确率：在需要调用API/工具的Agent中，是否选对了工具、填对了参数



**评测方案的落地框架**
一个完整的评测方案至少要包含：

1. 评测场景定义：明确要测什么能力（推理？多轮对话？工具调用？）

2. 数据集构建：自建还是用公开基准？数据分布是否覆盖典型场景和边界情况？

3. 指标选取：客观指标+主观指标结合，单一指标说明不了全貌

4. 评测流程规范：包括prompt模板、few-shot设置、评测环境等，要保证可复现

5. 结果解读标准：如何判断“合格”或“优秀”，需要设定阈值



# 评测数据集

这里先介绍一下两个简单的数据集

**MMLU：衡量综合知识储备**
- 全称：Massive Multitask Language Understanding
- 包含：57个学科，从初等数学到法律、计算机科学
- 难度：每个问题有4个选项，要求模型具备跨领域的知识广度和深度
- 当前进展：GPT-5级别的模型在MMLU上已突破90%

详见：[https://huggingface.co/datasets/cais/mmlu](https://huggingface.co/datasets/cais/mmlu)

测评脚本示例：[https://github.com/antoniolobos/MMLU_test/blob/main/eval_mmlu.py](https://github.com/antoniolobos/MMLU_test/blob/main/eval_mmlu.py)
大致流程为
```
加载模型 → 遍历57个学科 → 每个学科用few-shot示例构建prompt → 模型推理 → 计算各选项概率 → 判断正确性 → 汇总统计
```


**GSM8K：衡量数学推理能力**

- 全称：Grade School Math 8K
- 包含：约8000道小学数学应用题
- 独特价值：不是简单考计算，而是考多步推理能力
典型题目："小王有5个苹果，他给了小李2个，又买了3个，他现在有几个？"——需要理解情境，完成多步运算

详见：[https://huggingface.co/datasets/openai/gsm8k](https://huggingface.co/datasets/openai/gsm8k)

测评脚本示例：
一种是直接判断回答中是否包含答案中的数字，比如，模型如果回答 5.0、5 dollars、5.00，评测器会通过规则把它转换成 5，算作正确；

另外一种就是利用更高级的模型（例如GPT-4o）直接判断回答是否准确，相当于请一个中立的裁判，调用其接口，直接返回布尔值。




**评测数据集的使用原则**
- 不能只刷榜：MMLU高分不代表在业务场景中好用，基准数据集有泄露风险
- 要自建业务数据集：公开基准用于横向对比，但最终决策要基于自己的业务场景数据
- 动态更新：大模型能力在快速提升，评测集也要随之迭代，避免“饱和”


# 结语：评测是AI时代的“度量衡”


评测能力正在成为AI从业者的核心竞争壁垒之一。不会评测，就无法判断模型是真进步还是假把式；不会评测，在众多模型面前只能是“盲选”。

大模型智能体评测，就像给AI立规矩、定标准。谁掌握了科学的度量方法，谁就能在这场AI竞赛中看得更清、走得更远。

最后三句话：
- 没有评测，就没有改进的方向
- 单一指标，说明不了全貌
- 公开基准用于对比，业务数据决定选择
