# RTMP 是什么

RTMP（Real-Time Messaging Protocol）是 Adobe 发明的一种实时流媒体协议，虽然 Flash 死了，但 RTMP 在推流领域依然是事实标准。几乎所有直播平台（B站、抖音、YouTube）的推流入口都是 RTMP 协议的。

一个 RTMP 推流地址长这样：

```
rtmp://localhost:1935/live/stream_key
         ↑             ↑       ↑
      服务器地址     应用名   流名称
```

- `1935` 是 RTMP 默认端口
- `live` 是应用名（nginx-rtmp 配置的 application name）
- `stream_key` 是流标识——观看端用同一个地址拉流（`rtmp://server/live/stream_key`）

# 快速搭建本地测试服务器

推流需要有一个"接收端"。最快的方式是用 nginx + nginx-rtmp-module：

```nginx
# nginx.conf
rtmp {
    server {
        listen 1935;
        chunk_size 4096;

        application live {
            live on;           # 开启直播
            record off;        # 不录制
        }
    }
}

http {
    server {
        listen 8080;
        location / {
            root /path/to/player;  # 放一个 hls.js 或 video.js 的播放页面
        }
    }
}
```

启动后，推流到 `rtmp://localhost:1935/live/test`，然后用 ffplay 或浏览器（通过 HLS/WebRTC 转封装）拉流验证。

也可以用已经安装好的现成服务——`mediamtx`（原 rtsp-simple-server）支持 RTMP、RTSP、WebRTC 多协议，一条命令启动：

```bash
# 一键启动
./mediamtx
# 推流地址: rtmp://localhost:1935/live/test
# 观看地址: http://localhost:8889/live/test (WebRTC)
```

# 推流的核心：输出 URL 从文件变成网络地址

在 FFmpeg API 里，推流和写文件用的是完全相同的代码路径——区别只在 `avformat_alloc_output_context2` 的第二个参数和 `avio_open` 的 URL：

```c
// 写本地文件
avformat_alloc_output_context2(&out_ctx, NULL, "mp4", "output.mp4");
avio_open(&out_ctx->pb, "output.mp4", AVIO_FLAG_WRITE);

// 推流到 RTMP
avformat_alloc_output_context2(&out_ctx, NULL, "flv", "rtmp://localhost:1935/live/stream");
avio_open(&out_ctx->pb, "rtmp://localhost:1935/live/stream", AVIO_FLAG_WRITE);

// 后面的 avformat_write_header / av_interleaved_write_frame / av_write_trailer 
// 完全一样！
```

这里有个关键差异——封装格式从 `mp4` 变成了 `flv`。

**为什么推流用 FLV 而不是 MP4？** MP4 的文件头（`moov` box）只有在写入完成后才知道完整的帧索引，所以 `av_write_trailer` 之前无法推流——客户端拿到不完整的头部根本无法开始播放。FLV 没有这个问题，它的每个 tag 都是自包含的，可以流式产出。这就是 RTMP 底层传输 FLV 格式的原因。

# 推流端的完整代码

直接把上一篇录制器的输出目标改成 RTMP 地址，就是推流端：

```c
#include <libavformat/avformat.h>
#include <libavcodec/avcodec.h>
#include <libavdevice/avdevice.h>
#include <libswscale/swscale.h>
#include <libswresample/swresample.h>

int main() {
    avdevice_register_all();
    
    // ========== 1. 打开摄像头 ==========
    AVFormatContext *cam_ctx = NULL;
    AVInputFormat *dshow = av_find_input_format("dshow");
    AVDictionary *opts = NULL;
    av_dict_set(&opts, "video_size", "1280x720", 0);
    av_dict_set(&opts, "framerate", "30", 0);
    avformat_open_input(&cam_ctx, "video=Integrated Camera", dshow, &opts);
    av_dict_free(&opts);
    
    // ========== 2. 打开麦克风 ==========
    AVFormatContext *mic_ctx = NULL;
    av_dict_set(&opts, "sample_rate", "44100", 0);
    avformat_open_input(&mic_ctx, "audio=Microphone", dshow, &opts);
    av_dict_free(&opts);
    
    // ========== 3. 初始化编码器（同上一篇） ==========
    // 视频：H.264, baseline, ultrafast, zerolatency
    // 音频：AAC, 44100Hz, 立体声, 128kbps
    
    // ========== 4. 创建 RTMP 输出 ==========
    AVFormatContext *rtmp_ctx = NULL;
    avformat_alloc_output_context2(&rtmp_ctx, NULL, "flv",
        "rtmp://localhost:1935/live/stream");
    
    AVStream *video_st = avformat_new_stream(rtmp_ctx, NULL);
    avcodec_parameters_from_context(video_st->codecpar, video_enc);
    
    AVStream *audio_st = avformat_new_stream(rtmp_ctx, NULL);
    avcodec_parameters_from_context(audio_st->codecpar, audio_enc);
    
    // 打开网络连接
    avio_open(&rtmp_ctx->pb, "rtmp://localhost:1935/live/stream", AVIO_FLAG_WRITE);
    avformat_write_header(rtmp_ctx, NULL);
    
    // ========== 5. 主循环 ==========
    int64_t start_time = av_gettime();
    
    while (streaming) {
        // 视频采集 → 编码 → 推流
        if (av_read_frame(cam_ctx, cam_pkt) >= 0) {
            avcodec_send_frame(video_enc, enc_frame);
            while (avcodec_receive_packet(video_enc, video_pkt) >= 0) {
                av_packet_rescale_ts(video_pkt, video_enc->time_base, video_st->time_base);
                video_pkt->stream_index = video_st->index;
                av_interleaved_write_frame(rtmp_ctx, video_pkt);
                av_packet_unref(video_pkt);
            }
        }
        
        // 音频采集 → 编码 → 推流（逻辑同上）
        if (av_read_frame(mic_ctx, mic_pkt) >= 0) {
            // ... 重采样 → 编码 → av_interleaved_write_frame ...
        }
    }
    
    // ========== 6. 收尾 ==========
    av_write_trailer(rtmp_ctx);
    avio_closep(&rtmp_ctx->pb);
}
```

# 推流中的关键帧和 GOP 策略

直播场景下，GOP（Group of Pictures）的配置比录制更重要。

**`gop_size` 决定关键帧间隔**。设为 `fps * 2`（60 帧 = 2 秒一个 I 帧），意味着新观众最多等 2 秒就能看到画面。设太大（比如 250 帧 ≈ 8 秒），新观众进直播间要等很久才出画面。设太小，I 帧太频繁导致码率飙升。

```c
video_enc->gop_size = 30 * 2;     // 每 2 秒一个关键帧
video_enc->keyint_min = 30;       // 至少每 1 秒一个关键帧
video_enc->max_b_frames = 0;      // 直播建议关闭 B 帧
```

**关闭 B 帧有两个好处**：延迟更低（不需要等后续帧），编码更快。虽然压缩率略降，但直播场景延迟优先于码率。

# 动态码率：根据网络状况调整

推流到公网时，实时检测上传带宽并动态调整码率是刚需。最简单的做法是检查输出缓冲区的堆积量：

```c
// 每个关键帧位置检查一次
if (video_pkt->flags & AV_PKT_FLAG_KEY) {
    int buffer_size = rtmp_ctx->pb->bytes_in_buffer;  // 待发送的缓冲数据
    
    if (buffer_size > 500 * 1024) {    // 缓冲超过 500KB，降码率
        video_enc->bit_rate = video_enc->bit_rate * 0.8;
        if (video_enc->bit_rate < 500000) video_enc->bit_rate = 500000;
    } else if (buffer_size < 100 * 1024) {  // 缓冲很空，可以升码率
        video_enc->bit_rate = video_enc->bit_rate * 1.1;
        if (video_enc->bit_rate > 5000000) video_enc->bit_rate = 5000000;
    }
    
    printf("当前码率: %ld kbps, 缓冲: %d KB\n",
           video_enc->bit_rate / 1000, buffer_size / 1024);
}
```

这只是个简化版的示范。生产环境会有更复杂的 ABR（Adaptive Bitrate）策略——结合丢包率、RTT、吞吐量多个指标综合决策。

# 设置 MetaData：让播放器认识你的流

RTMP 流的元数据（分辨率、编码格式、码率）对于播放端的正确初始化解码很重要。FLV 的 metadata 在 `avformat_write_header` 时自动写入，但你需要确保编码器参数已经正确设置好。

也可以手动加一些自定义元数据：

```c
av_dict_set(&rtmp_ctx->metadata, "title",    "My Live Stream", 0);
av_dict_set(&rtmp_ctx->metadata, "author",   "Streamer", 0);
av_dict_set(&rtmp_ctx->metadata, "copyright","2026", 0);
```

# 推流断线重连

公网推流不可能不遇到断线。实现一个简单的重连机制：

```c
int reconnect_count = 0;
const int max_reconnect = 5;

while (streaming) {
    if (av_interleaved_write_frame(rtmp_ctx, video_pkt) < 0) {
        fprintf(stderr, "推流断开，尝试重连... (%d/%d)\n",
                reconnect_count + 1, max_reconnect);
        
        if (++reconnect_count > max_reconnect) {
            fprintf(stderr, "重连失败，停止推流\n");
            break;
        }
        
        // 关闭旧连接
        av_write_trailer(rtmp_ctx);
        avio_closep(&rtmp_ctx->pb);
        
        // 等待一会儿再重连
        av_usleep(2000000);  // 2 秒
        
        // 重新打开连接
        avio_open(&rtmp_ctx->pb, "rtmp://localhost:1935/live/stream",
                   AVIO_FLAG_WRITE);
        avformat_write_header(rtmp_ctx, NULL);
        
        // 强制刷新编码器（下一个必须是关键帧）
        enc_frame->pict_type = AV_PICTURE_TYPE_I;
    } else {
        reconnect_count = 0;  // 写入成功后重置计数
    }
}
```

重连后第一帧必须是关键帧，否则播放端解码不了。用 `enc_frame->pict_type = AV_PICTURE_TYPE_I` 告诉编码器 "下次编码强制输出 I 帧"。这在 H.264 中相当于 IDR（Instantaneous Decoder Refresh）帧，播放端收到后可以立即开始解码。

推上去之后，用 ffplay 验证：

```bash
# 或者用 VLC → 媒体 → 打开网络串流
```

# 小结

推流和录制的代码几乎一样——改输出 URL 和封装格式即可。真正多出来的是网络层要考虑的问题：

| 问题 | 方案 |
|------|------|
| 封装格式 | FLV（流式），非 MP4（需要完整 moov） |
| 关键帧策略 | GOP 2秒，关闭 B 帧 |
| 网络波动 | 动态码率 + 断线重连 |
| 重连后首帧 | 强制 IDR 帧 |
| 延迟优化 | preset=ultrafast, tune=zerolatency |
