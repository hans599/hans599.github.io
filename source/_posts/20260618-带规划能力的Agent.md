# 前言：为什么需要规划和多工具协同？  
  
- 单工具Agent的局限性（只能一问一答，无法处理复杂任务）

- 复杂任务的典型特征：多步骤、有依赖关系、需要动态决策



# 工具调用模式的演进

- 模式一：循环式工具选择（Function Calling）—— 模型逐轮决策，适合简单任务

- 模式二：计划驱动执行（Plan-then-Execute）—— 先生成全局计划，再执行，适合多步任务

- 模式三：程序化工具编排—— 将复杂逻辑下沉到代码，适合大规模数据处理

参考博客：[大模型工具使用的三次进化：从 Function Calling 到程序化编排](https://www.datalearner.com/blog/llm-tool-use-evolution-programmatic-calling)



# Plan-and-Solve：让Agent学会先规划

Plan-and-Solve的核心思想：先制定计划，再按计划执行。减少盲目调用，提高任务完成率


- OpenAI和Anthropic的实践：引导模型在调用工具前进行显式规划

- 规划工具的实现方式：通过一个“思考与规划”工具让模型结构化输出
- 

参考博客：
[如何让 Agent 规划调用工具](https://news.qq.com/rain/a/20250522A01SKV00?suid=&media_id=)


为什么规划能提升效果？
- 减少盲目调用：有全局视角，避免“走一步看一步”的试错
- 提高任务完成率：明确依赖关系（例如先分析结构，再统计指标，最后生成文档）

论文支持：ReAct论文和后续研究都表明，显式规划能显著提升多步任务的成功率 
[Architecting Resilient LLM Agents:
A Guide to Secure Plan-then-Execute Implementations](https://browse-export.arxiv.org/pdf/2509.08646#6#4)


简单代码示例：
```py
def planner_node(state: AgentState):
    """规划节点：LLM生成执行计划"""
    prompt = f"""
    用户需要分析以下Python代码并生成文档。
    
    可用工具：
    1. analyze_code_structure - 解析代码结构
    2. count_code_metrics - 统计代码指标
    3. generate_doc_template - 生成文档模板
    
    请制定一个执行计划，按顺序列出需要调用的工具。
    计划格式：
    Step 1: [工具名] - [目的]
    Step 2: [工具名] - [目的]
    ...
    """
    response = llm.invoke(prompt)
    return {"plan": response.content}
```


# Self-Refine：让Agent学会自我反思

Self-Refine：让Agent评估自己的输出，发现问题后自动修正，模拟人类的“写完检查一遍”过程

核心流程：
```
生成 → 评估 → 合格？→ 是 → 输出
              ↓ 否
            修正 → 重新评估
```

在LangGraph中通过条件边实现，
```py
def reviewer_node(state: AgentState):
    """审查节点：检查文档质量，决定是否重新生成"""
    prompt = f"""
    请审查以下文档，判断质量：
    {state["doc"]}
    
    评估标准：
    1. 是否包含所有函数/类的说明？
    2. 参数描述是否完整？
    3. 是否有示例代码？
    
    如果质量合格，回复 PASS。
    如果需改进，明确指出问题，回复 IMPROVE: [问题描述]
    """
    response = llm.invoke(prompt)
    return {"review": response.content}

def should_continue(state):
    """条件边：决定下一步是结束、重试还是转人工"""
    # 1. 如果审查通过
    if "PASS" in state["review"]:
        return END
    # 2. 如果超过最大重试次数，转人工审查
    if state["iteration"] >= 3:
        return "human_reviewer"  # 名称改为 human_reviewer
    
    # 3. 否则，重新生成
    return "doc_generator"

# 然后，在 workflow 中添加一个 'human_reviewer' 节点
workflow.add_node("human_reviewer", human_review_node)
    
```

研究表明，在Plan-then-Execute架构中加入重规划节点（replanner），能让Agent根据执行结果动态调整计划，显著提升鲁棒性。
[Architecting Resilient LLM Agents:
A Guide to Secure Plan-then-Execute Implementations](https://browse-export.arxiv.org/pdf/2509.08646#6#4)

重规划节点接收：1. 原始目标；2. 当前计划；3. 已执行步骤及其结果。然后判断：继续执行、生成新计划，还是任务完成。
