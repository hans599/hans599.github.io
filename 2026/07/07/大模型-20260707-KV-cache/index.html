大模型推理的"加速引擎"：从 QKV 到 KV Cache

Posted on 2026-07-07 Edited on 2026-08-07 In 大模型

Attention 机制的基石：QKV

QKV 是 Transformer 架构中 Attention 机制的核心三要素，分别代表 Query（查询）、Key（键） 和 Value（值）。

一个经典的类比是图书检索系统：

  • Query（查询）：你在图书馆检索时输入的关键词。它表达了”我想找什么”。
  • Key（键）：图书的索引标签或标题。它描述了”每本书是关于什么的”。
  • Value（值）：图书的实际内容。它是系统最终要返回给你的”有用信息”。

在 Transformer 中，每个输入 Token 都会通过三个不同的线性变换矩阵（(W_Q, W_K, W_V)）分别生成其对应的 Q、K、V 向量。注意，同一个 Token 的 Q、K、V 是不同的，它们服务于不同的目的：Q 用于”询问”，K 用于”被匹配”，V 用于”提供内容”。

Attention 机制的完整数学定义

注意力机制（Attention Mechanism）是 Transformer 架构的核心组件，其基本形式为缩放点积注意力（Scaled Dot-Product Attention），数学公式如下：

$$
\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right) V
$$

其中：

  • $Q$（Query，查询矩阵）：由当前待处理位置的输入经过线性变换得到，代表“我想查找什么信息”。
  • $K$（Key，键矩阵）：由所有位置的输入经过线性变换得到，代表“我包含了什么标签/索引”。
  • $V$（Value，值矩阵）：同样由所有位置输入变换得到，代表“我实际存储的内容是什么”。

分步解析

第1步：$Q \times K^T$（计算相关性得分）
用每个 Token 的查询向量 $Q_i$ 与所有 Token 的键向量 $K_j$ 做点积，得到一个 $n \times n$ 的得分矩阵。
这一步回答了核心问题：“当前位置（Query）应该对序列中哪些位置（Key）给予关注？”
点积值越大，表示两个向量方向越一致，语义相关性越高。

第2步：缩放（$\div \sqrt{d_k}$）
将得分矩阵除以 $\sqrt{d_k}$，其中 $d_k$ 是键向量的维度。
原因是当 $d_k$ 较大时，点积结果容易取到极大或极小的值，导致后续 Softmax 函数的梯度进入饱和区（梯度接近 0），影响训练稳定性。缩放操作可将方差控制在 1 附近，保持梯度平稳。

第3步：Softmax（归一化为权重）
对缩放后的得分矩阵按行（每个 Query 单独）施加 Softmax 函数，将其转化为 0~1 之间的概率分布，且每行求和为 1。
此时得到的矩阵即为注意力权重矩阵：权重越高，表示该 Query 对对应 Key 位置的关注度越高。

第4步：加权求和（$\times V$）
用上一步得到的注意力权重矩阵去加权所有 Token 的值向量 $V$，得到最终的输出矩阵。
这一步实现了信息聚合：每个位置的新表示，是序列中所有位置 Value 的加权和，权重由相关性决定。至此，模型完成了“根据 Query 从上下文中检索并提取信息”的全过程。

补充说明（多头机制）

实际工程中通常使用多头注意力（Multi-Head Attention），即并行运行 $h$ 组独立的上述注意力计算，每组使用不同的线性投影矩阵，最后将各头输出拼接并再投影一次。
这样做可以让模型在不同子空间中捕获不同类型的依赖关系（如语法、语义、位置等），显著提升表达力。

原始论文表述（《Attention Is All You Need》）

“An attention function can be described as mapping a query and a set of key-value pairs to an output, where the query, keys, values, and output are all vectors. The output is computed as a weighted sum of the values, where the weight assigned to each value is computed by a compatibility function of the query with the corresponding key.”

图解 QKV 的完整计算流程

下面用表格逐步展示 QKV 如何协同工作。假设输入有 3 个 Token（例如 ["我", "爱", "AI"]），每个 Token 都通过各自的权重矩阵生成自己的 Q、K、V 向量（为便于展示，这里用标量数值代替真实向量）。

步骤一：Q 与 K 的点积（计算注意力分数）

用每个 Token 的 Query 向量与 所有 Token 的 Key 向量做点积，得到一个 $3 \times 3$ 的得分矩阵。
值越大，表示该 Query 与对应 Key 的语义相关性越高。

K1 (Token1) K2 (Token2) K3 (Token3)
Q1 (Token1) 0.8 0.2 0.1
Q2 (Token2) 0.3 0.7 0.4
Q3 (Token3) 0.1 0.5 0.9

每一行代表一个 Token 的 Q 对所有 Token 的 K 进行点积的结果。
例如：Token1 的 Q 与 Token1 自己的 K 得分最高（0.8），说明它最关注自己。

步骤二：Softmax 归一化（将得分转化为权重）

对得分矩阵的 每一行 单独施加 Softmax 函数，将每行得分转化为 0~1 之间的概率分布，且每行权重之和为 1。

K1 K2 K3 行和
Q1 0.55 0.30 0.15 1.00
Q2 0.20 0.50 0.30 1.00
Q3 0.10 0.35 0.55 1.00

Softmax 将原本的得分（如 0.8、0.2、0.1）转换为可解释的“注意力百分比”。
现在每行都可以直接作为加权求和的权重使用。

步骤三：加权求和（$\times V$）

用上一步得到的权重矩阵去加权所有 Token 的 Value 向量，生成每个 Token 的最终输出。

对于 Token1 的最终输出：
$\text{Output}_1 = 0.55 \times V_1 + 0.30 \times V_2 + 0.15 \times V_3$

对于 Token2 的最终输出：
$\text{Output}_2 = 0.20 \times V_1 + 0.50 \times V_2 + 0.30 \times V_3$

对于 Token3 的最终输出：
$\text{Output}_3 = 0.10 \times V_1 + 0.35 \times V_2 + 0.55 \times V_3$

每个 Token 的新表示，都是所有 Token 的 Value 的加权混合，混合比例由 Q 和 K 的相关性决定。

流程总结

Q 找 K 算”相关性得分” → Softmax 转成”注意力权重” → 用权重混合 V 得到”最终输出”

推理时 Attention 的重复计算问题

大模型生成文本时，采用 自回归（Autoregressive） 方式，即一个字一个字地生成。每生成一个新 Token，都需要 Attention 机制重新计算一次。

以生成 "猫" → "追" → "老" → "鼠" 为例：

  • 生成第 1 个字 “猫”：计算 [猫] 的 QKV。
  • 生成第 2 个字 “追”：计算 [猫, 追] 的 QKV，重新计算了 “猫” 的 QKV。
  • 生成第 3 个字 “老”：计算 [猫, 追, 老] 的 QKV，重新计算了 “猫” 和 “追” 的 QKV。
  • 生成第 4 个字 “鼠”：计算 [猫, 追, 老, 鼠] 的 QKV，重新计算了 “猫”、”追”、”老” 的 QKV。

问题的严重性

随着生成的 Token 越来越多，重复计算的量呈平方级增长（复杂度 $O(n^2)$）。这是导致大模型推理慢、成本高的根本原因之一。

解决方案：KV Cache（键值缓存）

核心思想很简单：已经算过的 K 和 V 不要再重复算了，存起来复用。

生成步骤 无 KV Cache（重复计算） 有 KV Cache（复用缓存）
第1步生成”猫” 计算 Q1, K1, V1 计算 Q1, K1, V1，存入缓存
第2步生成”追” 重新计算 K1, V1 + 计算 K2, V2 直接复用缓存的 K1, V1，只算 K2, V2
第3步生成”老” 重新计算 K1,V1,K2,V2 + 算 K3,V3 复用 K1,V1,K2,V2，只算 K3,V3
第4步生成”鼠” 重新计算全部 + 算 K4,V4 复用全部已有，只算 K4,V4

效果：将 $O(n^2)$ 的重复计算降为 $O(n)$，推理速度大幅提升。这也是为什么主流推理框架（如 vLLM、llama.cpp、TensorRT-LLM）都强制开启 KV Cache。

为什么只缓存 KV，不缓存 Q？

虽然 K 和 V 可以复用，但 每个新 Token 的 Q 必须重新计算，因为它是”当前想查什么”的表示，每一步都在变化。

所以在自回归推理中：

  • K 和 V：缓存 + 增量计算
  • Q：每次从头算（但只有一个新 Token 的 Q，开销很小）

每个 Token 只会在它刚进入序列的那一步充当“查询者”（生成 Q），之后它永远只充当“被查询的资料库”（贡献 K 和 V）。

所以“猫”的 Q 在第 2 步用完后就被丢弃了，但这完全不影响“猫”作为 K 和 V 在后续所有步骤中被反复使用。

这就是 KV Cache 设计的底层逻辑：Q 是一次性的“查询请求”，K/V 是永久的“资料档案”。

这是理解 KV Cache 设计的关键。在 Attention 计算中，历史和未来对 Q 的需求是完全不同的。

历史的 Q 已经没用了

在生成第 $t$ 个 Token 时，我们需要计算的是当前 Token 的 Query 与所有历史 Token 的 Key 之间的注意力分数。这意味着：

  • 历史的 Query（$Q_1, Q_2, \dots, Q_{t-1}$）只在它们被生成的那个时刻有用
  • 一旦某个历史 Token 生成了它的 Query，这个 Query 就再也没有用处了
  • 我们真正需要的是当前 Token 的 Query（$Q_t$） 去和历史的所有 Key 做计算

历史的 K 和 V 需要被反复使用

与 Query 不同，Key 和 Value 一旦被生成，就需要被后续所有 Token 反复使用：

  • 当生成第 $t+1$ 个 Token 时，它的 Query 需要和所有历史 Token 的 Key 做点积
  • 同样，第 $t+2$ 个 Token 也需要和这些 Key 做点积
  • 历史的 V 同样会被后续的每个 Token 用于加权求和

关键洞察：随着序列变长，每个历史 K 和 V 被使用的次数越来越多（从 1 次增长到 $n$ 次），这是缓存它们能带来平方级加速的本质原因。

训练 vs 推理：为什么训练时不用 KV Cache？

训练推理核心差异对比

对比维度 训练阶段 推理阶段
输入长度 固定（如 2048 tokens），全部已知 动态增长，逐步生成（1 → 2 → 3 → … → n）
输入内容 完整序列（包含 ground truth） 仅包含已生成的 Token，未来 Token 未知
Attention 计算方式 并行计算所有 Token 的注意力 串行计算，每步只为新增 Token 计算 Attention
是否重复计算 ❌ 否，一次性计算所有位置的 Q/K/V ✅ 是，历史 Token 的 K/V 被反复使用
是否使用 KV Cache ❌ 不使用 ✅ 必选（几乎所有推理引擎都强制开启）
Q 的来源 所有 Token 的 Q 同时计算 只计算当前新增 Token 的 Q
K/V 的计算 所有 Token 的 K/V 同时计算 历史 K/V 从缓存复用，只算新增 Token 的 K/V
计算复杂度 $O(n^2 \cdot d)$（一次 Forward） 无 Cache: $O(n^2 \cdot d)$（每步累加）
有 Cache: $O(n \cdot d)$
显存占用 需要存储所有中间激活值（用于反向传播） 需要存储 KV Cache（随序列长度线性增长）
Batch Size 较大（充分利用 GPU 并行） 通常较小（受 KV Cache 显存限制）

为什么训练不用 KV Cache？

原因 详细说明
不需要生成 训练时所有 Token 已知，不存在”逐步预测”的过程
并行计算 所有位置同时计算，每个 Token 的 K/V 只用一次
反向传播需求 需要保存中间激活值用于梯度计算，KV Cache 反而增加显存压力
Teacher Forcing 训练时使用真实 Token 作为输入，不依赖自己的预测

为什么推理必须用 KV Cache？

原因 详细说明
自回归生成 每步只能生成一个 Token，必须逐步进行
历史 K/V 被反复查询 每个新增 Token 的 Q 都要查询所有历史 K
避免 $O(n^2)$ 重复计算 不缓存会导致计算量随序列长度平方增长
实际部署必须优化 长文本生成（如 4096 tokens）无 Cache 几乎不可用

总结

概念 核心要点
QKV Attention 机制的三个核心角色：
• Q（Query，查询）：代表“当前 Token 想查什么信息”
• K（Key，键）：代表“每个 Token 的关键索引/标签”，用于被查询匹配
• V（Value，值）：代表“每个 Token 存储的实际内容”，用于输出聚合
Attention 计算公式 $\text{Attention}(Q, K, V) = \text{softmax}\left(\dfrac{QK^T}{\sqrt{d_k}}\right) V$
三步走：
① $QK^T$ 算相关性得分
② Softmax 归一化为注意力权重
③ 加权求和 $V$ 得到最终输出
KV Cache 缓存历史 Token 的 K 和 V，避免自回归生成时的重复计算
复杂度变化：$O(n^2) \rightarrow O(n)$
是所有主流推理引擎（vLLM、llama.cpp、TensorRT-LLM）的标配优化
为什么只缓存 KV，不缓存 Q？ • 历史 Q：只在生成对应 Token 的那一刻有用，用完即弃
• 历史 K/V：被后续所有新 Token 的 Q 反复查询和加权
• 复用次数：第 $i$ 个 Token 的 K/V 被使用 $n-i+1$ 次
训练 vs 推理 • 训练阶段：所有 Token 同时输入，并行计算一次性完成，重复计算问题不存在，不用 KV Cache
• 推理阶段：自回归生成，历史 K/V 被反复查询，重复计算严重，必须用 KV Cache
