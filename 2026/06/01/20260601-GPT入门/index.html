$$
\text{attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V
$$

因此，在此处将跳过对注意力机制的解释。你也可以参考 Lilian Weng 的Attention? Attention!和 Jay Alammar 的Visualizing A Neural Machine Translation Model，这两篇文章也是对注意力机制的精彩讲解。

Self

当 q（查询）、k（键）和 v（值）都来自同一个源时，我们执行的就是自注意力（self-attention），即让输入序列自己与自己进行注意力计算。

例如，如果我们的输入是“Jay went to the store, he bought 10 apples.”（杰伊去了商店，他买了10个苹果。），我们会让“he”（他）这个词关注所有其他词，包括“Jay”（杰伊），这意味着模型可以学会识别出“he”指的是“Jay”。

Causal

我们当前的自注意力设置有一个问题：我们的输入可以“看到未来”的信息！

例如，如果输入是 [“not”, “all”, “heroes”, “wear”, “capes”]，在自注意力计算中，“wear”（位置 3）能够看到“capes”（位置 4）。这意味着模型在预测“wear”这个词时，输出概率会产生偏差，因为它已经提前知道了正确答案是“capes”。

这样做显然不行——模型会简单地学会：对于第 i 个位置的输入，正确答案可以直接从第 i+1 个位置复制过来。
解决方案：因果掩码（Causal Masking）。为了防止这种情况，我们需要修改注意力矩阵，隐藏或屏蔽掉“未来”的信息，让每个位置只能看到当前及之前的位置，不能看到之后的位置。

Multi-Head

我们可以通过执行 n_head 个独立的注意力计算来进一步改进实现，也就是将查询（queries）、键（keys）和值（values）拆分成多个头：

请注意，这样会将每个注意力计算的维度从 n_embd 降低到 n_embd / n_head。这是一个权衡。在维度降低的情况下，我们的模型在进行注意力关系建模时，获得了额外的子空间。例如，也许一个注意力头负责将代词与其所指代的人连接起来；另一个头可能负责按句号对句子进行分组；还有一个头可能仅仅用于识别哪些词是实体、哪些不是。不过，这很可能只是另一个神经网络的黑箱而已。

我们编写的代码是通过循环（一次一个）按顺序对每个头执行注意力计算，这样效率不是很高。在实践中，你应该希望这些计算是并行进行的。为了简单起见，我们这里就保持顺序执行。

概念 说明
为什么拆分成多个头 让模型从不同的表示子空间中学习信息，每个头关注不同的特征关系
头数 n_head 超参数，例如 GPT-2 使用 12 个头，GPT-3 使用 96 个头
每个头的维度 n_embd / n_head，保证总计算量不变

多头注意力其实可以类比卷积神经网络中同一层的多个卷积核：

  • CNN 中：32 个卷积核 → 输出 32 个通道 → 每个核检测不同的特征（边缘、纹理、颜色等）

  • Multi-Head Attention 中：12 个头 → 输出拼接成 12 × (n_embd/12) = n_embd → 每个头捕捉不同的关系（语法依赖、指代关系、局部上下文等）

代码部分 含义
x, y = inputs[:-1], inputs[1:] 将输入序列拆分为：x 是前缀（除最后一个token），y 是目标（除第一个token）。用于自回归预测每个位置的下一个token。

Training

训练 GPT 对于神经网络来说是非常标准的（相对于损失函数做梯度下降）。当然，在训练 GPT 时，你还需要使用一套标准的技巧（比如使用 Adam 优化器、找到最优学习率、通过 dropout 和/或权重衰减进行正则化、使用学习率调度器、使用正确的权重初始化、批处理等等）。

训练出好用的 GPT 模型的真正秘诀在于能够同时扩展数据和模型规模，而这正是真正的挑战所在。

对于扩展数据，你需要一个庞大、高质量且多样化的文本语料库。

  • 庞大：意味着数十亿个 token（TB 级数据）。例如，可以看看 The Pile，这是一个用于大语言模型的开源预训练数据集。

  • 高质量：意味着需要过滤掉重复样本、格式不规范的文本、不连贯的文本、垃圾文本等。

  • 多样化：意味着包含不同的序列长度、涉及众多不同主题、来自不同来源、拥有不同视角等。当然，如果数据中存在任何偏见，都会反映到模型中，所以你也需要格外注意这一点。**

将模型扩展到数十亿参数涉及到大量的工程工作（和大量的金钱，哈哈）。训练框架可能会变得异常冗长和复杂。推荐阅读 How to Train Really Large Models on Many GPUs?。
此外，相关的论文还可以阅读 NVIDIA 的Megatron、Cohere 的训练框架、Google 的 PALM，以及开源的mesh-transformer-jax （用于训练 EleutherAI 的开源模型）等等。

Stopping Generation

我们当前的实现需要事先精确指定要生成的 token 数量。这并不是一个好方法，因为这样生成的结果要么太长，要么太短，要么在句子中间被截断。

为了解决这个问题，我们可以引入一个特殊的句子结束（EOS）token。在预训练期间，我们将 EOS token 追加到输入的末尾（例如：tokens = [“not”，“all”，“heroes”，“wear”，“capes”，“.”，“<|EOS|>”]）。在生成过程中，我们只需在遇到 EOS token（或达到某个最大序列长度）时停止即可。

GPT-2 在预训练时没有使用 EOS token，所以我们不能在我们的代码中使用这种方法，但如今大多数大语言模型都使用了 EOS token。

Fine-tuning

“我们在训练部分简要提到了微调。回顾一下，微调是指我们复用预训练的权重，在某些下游任务上重新训练模型。我们称这个过程为迁移学习。

理论上，我们可以使用零样本或少样本提示来让模型完成我们的任务，但是，如果你有带标签的数据集，那么对 GPT 进行微调将会产生更好的效果（这种效果会随着更多数据和更高质量数据的加入而提升）。

Classification Fine-tuning

在分类微调中，我们给模型一些文本，并要求它预测文本所属的类别。例如，考虑 IMDB 数据集，其中包含将电影评为“好”或“差”的评论

为了微调我们的模型，我们用分类头替换掉语言模型头，并将其应用于最后一个 token 的输出：

我们只使用最后一个 token 的输出 x[-1]，因为对于整个输入，我们只需要产生一个概率分布，而不是像语言建模那样产生 n_seq 个分布。我们特别选择了最后一个 token（而不是比如第一个 token 或所有 token 的组合），因为最后一个 token 是唯一被允许关注整个序列的 token，因此它拥有关于整个输入文本的信息。

为什么用最后一个 token？

原因 说明
因果掩码（Causal Masking） 在 GPT 的因果自注意力中，第 $i$ 个 token 只能看到 $0 \dots i$ 位置的 token
最后一个 token 的优势 它是唯一能看到整个输入序列（所有 token）的 token
信息聚合 经过多层 Transformer 后，最后一个 token 的隐状态自然聚合了整个序列的语义信息

Instruction Fine-tuning （指令微调）

如今，大多数最先进的大语言模型在预训练之后还会经历一个额外的指令微调步骤。在这一步中，模型会在数千个由人工标注的指令提示 + 回答配对数据上进行（生成式）微调。指令微调也可以称为监督微调，因为这些数据是人工标注的（即监督学习）。

那么指令微调的好处是什么呢？虽然预测维基百科文章中的下一个单词能让模型擅长续写句子，但这并不能让它特别擅长遵循指令、进行对话或总结文档（这些都是我们希望 GPT 能做的事情）。在人工标注的指令 + 回答配对数据上对其进行微调，是一种教会模型如何变得更有用的方法，并让它们更容易交互。我们称之为AI 对齐，因为我们正在让模型的行为符合我们的期望。对齐是一个活跃的研究领域，并且不仅仅包括遵循指令（还涉及偏见、安全性、意图等）。

这些指令数据具体长什么样？Google 的 FLAN 模型（FINETUNED LANGUAGE MODELS ARE ZERO-SHOT
LEARNERS）是在各种学术 NLP 数据集（这些数据集已经是人工标注的）上训练的。

另一方面，OpenAI 的 InstructGPT （Training language models to follow instructions
with human feedback）是在从他们自己的 API 收集的提示词上训练的。然后他们付费请标注员为这些提示词编写回答。

Parameter Efficient Fine-tuning （参数高效微调）

当我们在以上章节讨论微调时，我们假设更新的是模型的所有参数。虽然这种方式能带来最佳性能，但无论是从计算（需要对整个模型进行反向传播）还是从存储（每个微调后的模型都需要存储一份全新的参数副本）的角度来看，成本都很高。对于指令微调来说，这没问题，因为我们追求的是最佳性能，但如果你之后想针对各种不同的下游任务微调 100 个不同的模型，那就有问题了。

解决这个问题最简单的方法是只更新头部（分类头）并冻结（即设为不可训练）模型的其余部分。这能加快训练速度并大幅减少新参数的数量，但它的性能远不及全量微调（我们丢失了深度学习中的‘深度’）。

我们可以选择性地冻结特定层（例如，冻结除最后 4 层之外的所有层，或每隔一层冻结一层，或冻结除多头注意力参数之外的所有参数），这有助于恢复一些深度。这样做效果会好很多，但我们的参数效率会降低，训练加速也会减少。

全量微调（Full Fine-tuning，FFT）能最好但成本高（每任务一份完整模型）；简单冻结大部分层只训练头部会损失深度信息导致性能下降；选择性冻结部分层可以折中，但现代更推荐使用 LoRA 等参数高效微调（Parameter Efficient Fine-tuning，PEFT）方法。

方法 核心思想 可训练参数量 性能接近全量微调
LoRA 在权重矩阵旁添加低秩分解的可训练矩阵 约0.1-1% 是
QLoRA 将基座模型量化到4-bit，再附加低秩适配器进行微调 约0.1-1% 是（接近LoRA）
Adapter 在 Transformer 层间插入小型可训练模块 约0.5-5% 是
Prefix-Tuning 在输入前添加可训练的虚拟 token 约0.1% 部分任务

微调与量化的联系与区别

维度 微调 (Fine-tuning) 量化 (Quantization)
是否改变权重数值 是，通过梯度下降更新参数 否，只改变数值的表示形式
是否需要训练数据 需要 不需要（PTQ）或需要校准数据（QAT）
是否改变模型结构 可能（如添加 LoRA 层） 否
目的 让模型适应新任务/新知识 压缩模型，减少显存和加速推理
结果 模型能力改变 模型能力基本不变（略有损失）

微调改变模型”学什么”，量化改变模型”怎么存”——前者改能力，后者改精度，两者通常组合使用。

组合方式 流程 典型应用
先微调，再量化 训练（fp16）→ 微调（fp16）→ 量化到 int8/int4 生产部署最常见
量化感知微调 在微调过程中模拟量化损失 QLoRA（4-bit 基座 + fp16 LoRA）
量化后微调 量化后继续微调（难度大，精度损失大） 较少使用
