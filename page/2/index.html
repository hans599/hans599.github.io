Mutli-Agent的定义

多智能体系统是一种配置，其中两个或以上的 LLM 驱动型智能体协同工作，每个智能体拥有独立的角色、工具和记忆，以完成单个智能体无法独立处理的任务。这些智能体通过明确的交接、共享状态或群组聊天协调器（决定由谁发言）进行协调。每个智能体拥有独立的子追踪、交接跨度，并产生一个联合结果。像 CrewAI、AutoGen、Google ADK、LangGraph、OpenAI Agents SDK、Mastra、Strands、Pydantic-AI 和 Microsoft AutoGen Studio 等框架以不同的方式实现了这一模式。

什么是 Agent Skills——从 MCP 到 Skill 的自然延伸

学完 MCP 之后，你可能会思考一个问题：有了统一协议让 Agent 连接工具，但 Agent 怎么知道用这些工具完成复杂任务？

MCP 解决的是“用什么工具”，Skill 解决的是“怎么用工具完成任务”。两者是互补关系，不是替代关系。

Skill 的本质：一套结构化的指令和资源，教会 AI 完成特定任务，让 AI 按照标准规则干活。

MCP（Model Context Protocol）

Posted on 2026-06-22 Edited on 2026-08-07

为什么需要MCP？

在AI Agent开发中，一个反复出现的痛点是如何让大模型调用外部工具。传统方式下，每个工具都要单独写适配代码——模型A用一种Function Call格式，模型B用另一种，工具用Python写一套接口，用C++写又要重新封装。这种“碎片化”集成方式难以扩展。

MCP（Model Context Protocol）正是为解决这一问题而生。它由Anthropic于2024年底提出并开源，被视作AI领域的“USB-C接口”——为AI助手连接任何数据源或服务提供了统一标准。

MCP的核心理念：在LLM与外部世界之间建立标准化、双向的通信通道。过去M个模型对接N个工具需要M×N种适配，现在有了通用协议，不同模型与不同工具可以通过MCP这一“共同语言”无缝协作。

LangGraph实战

Posted on 2026-06-09 Edited on 2026-08-07

前言：为什么需要LangGraph？

手写ReAct的问题

实现一个简单的“思考-行动-观察”（ReAct）循环似乎并不难，但随着业务复杂度的提升，手写方式会暴露三个核心痛点：

  • 状态管理混乱：在多轮工具调用和推理步骤中，消息历史、中间结果、上下文等信息散落在各处，难以统一管理和持久化。

  • 复杂流程难以维护：当需要引入循环、条件分支、并行执行或人工介入时，手写的 while 循环和 if-else 会迅速演变成难以调试的“意大利面式”代码。

  • 没有现成的调试工具：Agent 的执行过程像一个“黑盒”，你很难清晰地看到它在每一步的思考、工具调用和状态变化，问题排查非常痛苦。
